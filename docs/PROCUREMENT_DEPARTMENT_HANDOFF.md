# 采购部门使用与验收手册

本手册覆盖手工采购与官方订单驱动的采购。两条流程共用采购复审、正式采购单、分批到货和审计。

## 交付边界

- ERP 保留平台原始订单、订单行、退款和履约事实；采购动作不会反写 Shopify 的订单、库存、付款或发货状态。
- MUKU 只读库存用于建议与对账，不修改 MUKU 看板、采集任务或共享盘。
- `null` 表示未知，`0` 只表示来源或人工核验明确确认的零；未知不能按零采购。
- 取消、退款、到货和历史申请不物理删除；页面按当前有效状态去重。
- 只有已验证官方订单可以自动转采购申请。本地 QA、测试单、服务费、安全库存追加量和超出真实订单缺口的策略取整量不能冒充订单需求。
- 页面会明确显示当前店铺覆盖数。现阶段如果只显示 BizFurniz 1/4，就是单店试点，未授权的 ZIMASYA、Kaguyasu、Anzhap 不能被表述为已纳入全公司采购。

## 角色与职责

| 角色 | 当前系统职责 |
| --- | --- |
| 管理员 admin | 可管理团队角色、承担指定申请的复审，并在本工作区为已批准申请开采购单、编辑采购单草稿和确认下单。负责人和唯一管理员不能降级。 |
| 操作员 operator | 可被指定为采购负责人，处理 SKU、建议、申请、供应商、采购单和到货；无复审或团队管理权限。 |
| 只读成员 viewer | 只读查看采购建议、申请、采购单和到货记录，不能被指定为采购负责人或复审人。 |
| 采购负责人（流程指派） | 指定负责人可提交、撤销申请，开采购单、编辑草稿、确认下单，以及取消草稿或关闭未到余量。一般操作员仅能办理自己负责的单据。 |
| 复审人（流程指派） | 只有申请中指定的管理员可批准或驳回；正式模式下不能与采购负责人相同。 |
| 到货登记 | 具备入库权限的仓库人员可按已下单采购单登记实际到货，不要求是原采购负责人。 |

开发开放模式只用于联调：为了方便更换 GPT 账号，当前登录账号可继续其他成员已分配但未完成的采购流程，每次操作仍记录实际账号。正式上线必须关闭该模式并恢复负责人/复审人岗位分离。
成员需先登录一次 ERP 才会出现在「系统管理 → 团队权限」。仍有未完成采购负责人或复审任务时，系统会阻止把其降为不具备相应权限的角色，避免采购单卡住。

### 人员离岗交接 SOP

负责人请假、离职或换班时，不要共用账号，也不要取消、删除或重建真实单据。由具备“团队管理”权限的管理员按以下步骤交接：

1. 在“采购申请”或“采购单 / 待到货”找到仍处于草稿、待复审或已批准状态的申请，点击 **重新指派**。采购单入口实际交接其来源申请，因此同一流程只需操作一次。
2. 核对页面显示的现任负责人和复审人，选择新采购负责人、新复审人，并填写至少 2 个字的真实原因。
3. 正式模式下，采购负责人和复审人必须是不同成员；负责人须有采购提交权限，复审人须为有复审权限的管理员。跨工作区成员、只读成员或已经结束的申请不能被指派。
4. 提交成功后刷新页面核对新负责人。跟随负责人指派的操作权立即转给新负责人。本工作区管理员仍可按管理员权限开单、改草稿或确认下单。
5. 申请已有采购单时，原采购单和历史记录保留，采购单的负责人随申请同步更新。到货登记按入库权限执行。
6. 如果提示“版本已变化”，说明另一人刚处理过该申请；刷新后重新核对，不能用旧页面覆盖。网络超时后在原弹窗重试会复用同一幂等键，不会重复交接。

每次交接都会追加保存交接前后负责人、复审人、原因、操作管理员和时间；不会改写既有审计或业务历史。

## 手工采购

1. 按编码或名称搜索商品 SKU。也可到「基础资料」补充 SKU 商品档案、供应商或收货仓。
2. 采购员打开「新建采购申请」，选择商品 SKU，填写数量和采购原因。商品名称、规格、尺寸、图片和介绍自动带出，可在本次申请中调整。新商品可从表单新增 SKU。图片支持上传，或使用可访问的图片链接。指定采购负责人和复审人后，点击「提交复审」。
3. 指定的管理员批准后，系统自动生成采购单草稿。管理员或采购负责人可核对商品信息、补齐供应商和交货条件，再确认下单。

手工申请可以在未接入 Shopify 或 MUKU 的工作区创建。系统采购建议仍按已验证的官方订单和库存数据时效校验。

### 批量维护商品资料

「采购管理 → 商品档案」可以按 SKU、名称及缺失的规格、尺寸、图片和介绍筛选。单条资料可直接编辑。批量补录现有 SKU 时，可导出当前筛选页的补录表，填写缺项后再导入。补录表保留 SKU 和参考资料，待填写列默认为空。

1. 在「采购管理 → 基础资料 → 批量导入 SKU」下载 Excel 模板。每行填写一个 SKU，最多 500 行。新建 SKU 需填写编码和商品名称。规格、尺寸、图片链接和商品介绍可随资料到齐逐步补充。
2. 上传 `.xlsx` 后核对预览中的新增、更新、未变更和错误。以当前工作区 SKU 编码匹配已有商品，空白单元格保留已存资料。图片列填写可访问的链接，图片文件可在商品档案中上传。
3. 确认导入后，新的采购申请会带出最新商品资料。已保存的申请和采购单保留各自的商品快照。

## 每日操作 SOP

### 1. 先检查数据是否可用于采购

进入 **采购管理 → 今日采购建议**，只在以下两项都正常时继续：

1. MUKU 库存显示“库存数据可用于采购”，生成时间与 ERP 最近同步时间均未过期。
2. Shopify 官方订单源已核验，店铺最近同步成功且没有失败、未来时间或本地 QA 标记。

页面刷新只重新读取 ERP；它不等于 Shopify 或 MUKU 已持续采集。显示“自动化尚未闭环”时，先按页面列出的配置或调度原因处理。

### 2. 处理 SKU 与库存阻断

- **平台 SKU 待映射**：在“SKU 映射”中把平台原始 SKU 归属到唯一 ERP SKU。原始值会保留。
- **MUKU SKU 未映射或歧义**：在采购建议的映射区人工选择 ERP SKU。不能靠相似名称强行合并。
- **MUKU 没有可用量**：只能在已经人工核对全仓可用量后录入人工库存确认，必须填写依据；确认最多有效 24 小时。
- **MUKU 已提供明确可用量**：系统始终优先使用 MUKU，人工值不能覆盖。
- **在途库存**：仅展示，不抵扣建议量，避免与 ERP 已下单未收数量重复计算。
- **采购策略**：可维护安全天数、安全库存、MOQ、包装量、交期和首选供应商；系统不会把没有官方订单依据的安全库存或策略取整量自动转成订单采购申请。

### 3. 生成采购申请

已知要买的商品和数量时，在「采购管理 → 新建采购申请」录入。负责人可直接提交复审，交由指定管理员批准。商品 SKU 可在申请中建立，供应商和收货仓在确认下单前补齐。

从采购建议发起时按以下步骤操作。

1. 勾选没有阻断且存在“可转官方订单”数量的行。
2. 指定采购负责人和复审人，填写交期或特殊要求。
3. 选择“保存草稿”或“创建并提交复审”。
4. 服务端会在创建、提交和批准时重新校验订单、库存、建议版本及人工确认有效期；页面上看到的旧数量不能绕过校验。

同一订单需求只能进入一张有效申请。重复点击或网络重放不会产生第二张有效申请。

### 4. 提交与复审

- 草稿只能由指定采购负责人提交或取消。
- 待复审申请只能由指定复审人批准或驳回。
- 驳回和草稿取消会释放需求，但保留申请和审计历史。
- 如果订单被取消、退款、履约或数量发生变化，系统会阻止旧申请继续流转或标记“源订单已变化，需复核”。不要通过改备注或重复点击绕过。

### 5. 生成并确认正式采购单

1. 管理员批准申请时，系统生成一张采购单草稿。采购单保留申请里的商品资料和原采购负责人，并记录实际操作人。历史已批准还没生成采购单的申请，可在「已批准待下单」筛选后点击「开采购单」。
2. 在草稿中核对并按需修改本单商品名称、规格、尺寸和图片。选择供应商和收货仓，填写交期、币种和各商品单价。付款、交付条款和备注可按实际填。
3. 点击「确认下单」一次保存并正式下单。系统保留供货方和收货信息，可在「采购单」打印并交给供应商。仓库在「待收货」登记实际到货。
4. 条件未谈妥时，可先保存已核对的内容，在「采购单」里预览或继续编辑。正式采购单的打印件保留本单商品信息和图片。页面版本过期时，刷新后重新核对。

同一已批准申请只能有一张有效采购单。取消的采购单保留历史后可重新生成。

### 付款进度

- 在采购单的金额栏打开「付款进度」，可按原币核对应付、已付净额、未付、待审批请款和已审批待结清金额。
- 采购员可提交预付款或尾款请款，授权审批人批准后进入待结清。财务按实际付款凭证登记并关联请款。付款冲正后，请款和采购单的余额随实际净额重新计算。
- 金额或币种尚不完整的单据在付款进度中显示待核。补齐正式采购单的应付金额后再登记实付。

### 6. 分批到货

1. 只有“已下单”或“部分到货”的采购单可以登记到货。
2. 页面固定显示采购单的收货仓，不能在到货时临时改到其他仓；逐行填写本批到货数量和备注。
3. 到货数量不能超过未收数量；网络超时或失败后在原弹窗重试会复用同一幂等键，不会重复增加库存。
4. 每次到货生成独立、不可变的到货记录，并增加 ERP 自有库存流水；不会覆盖 MUKU 库存。
5. 供应商确认无法继续交货时，由原采购负责人点击“关闭剩余量”并填写原因；系统保留原采购数量和已到数量，只释放未到部分供后续重新安排。

发现数量填多或整批错录时，不要继续登记下一批，应在“到货记录”点击 **冲正错录**：

1. 页面会先读取该到货单已有冲正历史，逐行显示原收、已冲正和剩余可冲正数量。
2. 勾选错录明细，填写本次冲正正整数和至少 2 个字的真实原因；数量不能超过剩余可冲正量。
3. 提交后系统新增冲正单和负向库存流水，回算采购单已收数量与状态；原到货单、原数量和历次冲正均永久保留。
4. 库存已消耗或被订单占用时，系统会拒绝直接冲正；先核对并解除真实库存占用，不能用改库或填假记录绕过。
5. 收货仓在采购单上就已固定。确认下单前发现仓库错误，应取消草稿并按真实仓重建；已下单或已收货的错仓不能靠临时切换仓库绕过，必须由管理员核对真实物流和审计记录后处理。

### 7. 日终核对

- “采购单 / 待到货”：核对已下单未收数量。
- “到货记录”：核对当日到货单、仓库、SKU 和件数。
- “历史”：核对驳回、取消、全部到货、短到关闭及取消采购单；历史保留不等于当前仍占用需求。
- 对同一日期范围，先逐笔核对真实订单，再核对汇总。平台账单与订单 API 口径不同，不能为凑金额修改原始订单。

## 常见阻断与处理

| 页面提示 | 处理方式 |
| --- | --- |
| 官方订单源未就绪 / 同步过期 | 由管理员检查店铺授权与后台对账；数据恢复前不转申请。 |
| 库存快照过期 / 仓库源时间未知 | 等待 MUKU 源与 ERP 同步恢复；不能以页面刷新或手工填 0 绕过。 |
| MUKU SKU 未映射 / 存在歧义 | 人工确认唯一 ERP SKU，保留原始映射依据。 |
| 人工库存确认过期 | 重新核对全仓真实可用量并续期；不能复制旧时间。 |
| 到货尚未反映在 MUKU | 等待 MUKU 源时间越过本次到货时间，防止重复采购。 |
| MOQ/包装取整超出订单缺口 | 不能自动转申请；采购负责人另行取得明确业务批准后再处理非订单需求。 |
| 源订单变化，需复核 | 停止转采购单；未形成有效采购单时走受控撤回并重新计算，已有采购单时由管理员按真实供应商状态处理。 |
| 负责人离岗或流程卡在旧负责人 | 由管理员在活跃申请或采购单点击“重新指派”，选择合格的新负责人和复审人并填写真实原因；不要共享旧账号或重建单据。 |
| 重新指派提示版本已变化 | 刷新并核对最新负责人、状态和版本后再提交；系统不会让旧页面覆盖他人的新操作。 |
| 采购单不可确认下单 | 补齐收货仓、预计交期、3 位币种和全部明细单价；旧版不完整草稿取消后按完整信息重建。 |
| 到货时提示收货仓不匹配 | 停止入库并核对采购单固定收货仓；不要选其他仓或进行数据改写。 |
| 到货数量超过未收数量 | 按真实剩余数量拆分登记，不修改历史到货记录。 |
| 冲正数量超过剩余可冲正量 | 刷新冲正窗口，按逐行显示的剩余量重新填写；不要重复冲正。 |
| 库存已占用或消耗，无法冲正 | 先核对销售订单预占和实际出库，解除真实占用后重试；系统不会把库存扣成负数。 |

## 严禁操作

- 不用销售汇总反推订单，不把库存搜索结果当成全量库存。
- 不把缺失、失败、无权限、未结算或未知值改成 `0`。
- 不跨币种直接合计采购金额。
- 不在 ERP 中复制或展示 Token、Cookie、App Secret、OAuth code 或共享盘凭证。
- 不删除、覆盖、移动或清理共享盘、UNC 路径、MUKU 数据或 ERP 历史记录。
- 未取得另行写权限前，不向平台修改订单、库存、付款或发货状态。

## 上线前一次性配置

1. 发布最新 ERP 版本并应用新增 D1 迁移；不覆盖已有数据库。
2. `ERP_ALLOWED_EMAILS` 第一位配置正式 owner，由该账号先初始化管理员，再增加其他邮箱或公司域名。
3. 关闭 `ERP_DEV_OPEN_ACCESS`，让采购负责人和复审人分别登录一次，再核对其数据库角色。
4. 配置 ERP 独立的 MUKU 只读密钥、Shopify OAuth/服务端凭证与凭证加密密钥；不得复用或破坏看板授权。
5. 配置受保护后台任务或 Sites MCP 计划任务，实际验证后才把调度状态变量设为 `true`。
6. 用一家真实 Shopify 店铺核对一个日期范围：完整分页、增量更新、重复运行不重复、取消/退款/多包裹更新正确。
7. 用一张非生产或经批准的小额采购申请完成：草稿 → 提交 → 复审 → 采购单 → 下单 → 分批到货 → 历史核对。

## 自动验收

在项目根目录运行：

```powershell
npm run test:procurement-acceptance
```

该命令固定单进程执行采购验收套件，覆盖：

- Shopify 分页、增量、断点续跑与重复同步幂等；
- 订单取消、退款、履约和行移除对采购需求的影响；
- SKU 映射与租户隔离；
- MUKU 快照失败保留旧有效数据、新鲜度 fail-closed；
- 采购建议、人工库存确认、在途不抵扣、MOQ/包装阻断；
- 申请防重复、负责人/复审人岗位分离与源数据重校验；
- 管理员受控重新指派、并发版本保护、负责人操作权同步转移，以及管理员代办下单的操作留痕；
- 采购单防重复、取消保留历史、分批到货、重复到货不重复入库，以及追加式错录冲正、库存占用保护和净收货汇总。

自动测试通过只证明代码规则成立，不等于线上店铺已授权、调度已运行或真实订单已逐笔验收；这些结果必须在发布后单独记录。
