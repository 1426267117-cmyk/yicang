请在当前 ERP 项目中开展多店铺订单数据接入。附件是现有 MUKU 数据看板的接入交接资料，不是要合并或部署的完整看板项目。

一、目标和边界
1. 只修改当前 ERP 工程及 ERP 自己的数据存储。现有 MUKU 看板 https://muku.44-224-46-201.sslip.io/ 保持原样；不得改动它的数据库、部署、访问权限、采集任务、凭证或已有授权。
2. 共享盘及 UNC 路径中的所有源文件、数据库、备份、快照和缓存永久只读，禁止删除、覆盖、替换、移动、清空、清理或运行其中的脚本。
3. 不把附件覆盖到 ERP 根目录。先放入 docs/muku-handoff/ 作为参考；reference/ 下都是源码参考文本，不能当作已安装的连接器直接运行。
4. 不上传 Gitee，不打开 Git 登录界面，不复制或展示密码、Token、Cookie、App Secret、DPAPI 凭证。ERP 凭证通过其后端密钥配置独立提供，不能改坏看板已有授权。

二、先检查和复用
先阅读 00_先读我.html、02_接入能力与缺口.json、03_看板只读接口目录.json、04_店铺与仓库映射.json、05_订单数据模型与验收.txt、06_官方资料与授权说明.txt 和 reference/README.txt。
检查当前 ERP 使用的框架、数据库、已有订单/商品/SKU/仓库模型、连接器、同步游标、调度和日志能力。优先复用已有结构，不另造一套冲突系统。
如果这是易仓官方商用系统而不是可维护源码的自研工程，先确认官方开放平台、扩展或导入能力；不要假装能改厂商后端或通过网页注入完成集成。

三、接入架构
1. 各平台官方订单 API -> ERP 的独立连接器 -> 原始订单/订单行/退款/履约事实 -> ERP 的业务管理与报表。
2. 看板现有只读接口仅用于辅助查询和对账，不能拿销售汇总反推订单，也不能把库存搜索当成全量库存导出。不要调用看板的任何写入接口。
3. 优先跑通一家 Shopify 店铺的只读订单接入，再扩展其他 Shopify、Amazon、Wayfair 和运去哪。
4. 优先复用附件中的 Shopify 请求、分页、订单行、重试和时区处理代码；根据 ERP 技术栈改造成独立模块。附件里的汇总函数不是完整订单落库接口，旧 REST 示例只作迁移参考，新开发按受支持的 Admin GraphQL 契约实施。
5. Amazon 采用官方 SP-API Orders 接入。当前资料没有提供已验证的完整 SP-API 授权；浏览器采集、领星内部 sid、广告 profileId 都不能当作正式 Seller ID 或授权。
6. Wayfair 优先确认供应商正式订单 API 授权；CSV、扣款和 WSP 广告解析可作历史回补或对账，不作为永久实时订单主来源。
7. 运去哪的库存、出库单、入库计划、运输轨迹要分别核验接口和权限。不能认为同一把轨迹 Key 自动拥有仓库库存和入库权限。发货单数、柜数、商品件数、SKU 数必须分开保存。

四、数据规则
保留全店原始订单，不预先剔除深圳归属商品、测试单、取消单、零金额单或 Pending 单。分别保存其状态和业务归属；在报表层决定是否计入。
订单主键至少使用 platform + store_id + source_order_id；订单行再加 source_order_line_id。SKU 必须保留原值，统一 SKU/仓库映射要可追溯，歧义映射不能强行合并。
同步同时覆盖创建和更新时间，保留原始时间及时区；先完整分页回补，再按更新时间增量同步，并定期重扫一个可配置重叠窗口。不能只按下单日抓一次而遗漏后续取消、退款或发货更新。
金额使用 decimal 或货币最小单位并保留 currency，区分商品额、折扣、运费、税、退款和实收；不跨币种直接求和。退款交易与退款对象分开核验，避免重复扣减。
缺失、失败、无权限、尚未结算与真实 0 是不同状态。未知保持 null，不用 0 补齐，不使用模拟数据冒充生产结果。
先只读同步，不向平台修改订单、确认发货、扣减库存或改变付款状态；这些写操作需要另行明确授权。

五、交付和验收
先列出现有可复用部分、ERP 字段映射、官方接口/权限缺口及实施顺序，然后在已具备条件的范围内推进 ERP 开发。
必须验证：订单和订单行全量分页；重复运行不重复入库；新建/更新/Pending/取消/部分退款/多包裹；断点重跑；失败保留旧有效数据；原始时间/币种/业务归属可追溯。
有真实权限时，以一个日期范围内的真实订单逐笔核对，再核对店铺汇总。订单 API 与 ShopifyQL、平台账单可能口径不同，应列桥接差异，不能为凑看板金额篡改原始订单。
如果缺少授权，明确列出“哪个平台、哪家店、哪个字段或权限、需要我完成什么”，但继续完成不依赖授权的数据模型、连接器框架、幂等、测试和文档。发现已有合适连接器、CLI 或官方能力，先核验再复用。
最后报告：已接通店铺、取得的真实字段、历史/增量覆盖、验证结果、未完成项，以及确认未改动 MUKU 看板和共享盘原始数据。
