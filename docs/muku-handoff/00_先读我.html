MUKU 数据看板 → ERP 接入交接包

整理日期：2026-10-30。用途：交给你正在开发的 ERP 项目，复用数据接入经验和代码。现有看板保持原样。

推荐交接方式：发送这个 ZIP，再粘贴提示词。不需要发送整个看板工程；这个包也不是新建的订单 API 或已经完成的 ERP 集成。

怎么发到 ERP 那边

  1. 如果在另一台电脑开发，发送完整 ZIP，解压到 ERP 项目的 docs/muku-handoff/。
  2. 如果同一电脑的另一个项目开发，把整个解压文件夹放到 ERP 可读取的位置，或在那边的 Codex 中引用该文件夹。
  3. 打开 开场提示词，整段复制给 ERP 项目的开发助手，并附上 ZIP/解压目录。
  4. 真实凭证在 ERP 后端按平台单独配置，不放进 ZIP 或提示词。先只读接订单，再讨论发货、库存扣减等写操作。

优先复用哪些部分

部分可复用内容当前状态
Shopify请求、分页、重试、订单行展开、时区和财务对账逻辑代码可复用；不是开箱即用的 ERP 连接器
Amazon报表回补、广告对账、币种/日期/归属检查；四店命名映射回补/对账参考；正式订单 API 待 ERP 核验
Wayfair历史回补及订单/财务对账，保留 PO 与扣款编号解析可复用；不等于已接好实时订单 API
运去哪 YQN读取客户端、分仓分页、业务编号、入库/运输字段标准化入库/发柜数据当前有实证；其他能力按接口核验
库存与 SKU标准 SKU/原始 SKU 双轨、仓库代码、库龄筛选、快照与来源时间辅助查询可用；全量初始化需补专用导出或直连源系统

Amazon SKU 销售接口仅可参考覆盖率和查询契约；当前数值不能作为完整销售事实接口存在，当前数据覆盖不可用于全量订单/销量
发柜销售预测业务编号去重、数量分层和可追溯参考算法事实与预测必须分开；预测不能作为 ERP 财务事实

应该采用的关系

平台官方订单 API → ERP 自己的连接器与原始订单库 → ERP 订单、库存、履约和财务管理。看板现有 GET 接口只作辅助查询与对账。

保留全店原始订单和业务归属，不把看板剔除后的销售额反推为订单，不把发货单当柜子，不把未知字段补成0。

从哪里开始读

  • 接入能力与缺口：区分代码可用、数据实证和未取得的授权。
  • 现有只读接口地址和限制：没有新增接口，也没有写入接口。
  • 店铺与仓库映射：区分看板标识与平台正式ID。
  • 订单模型、同步与验收：给 ERP 落库和对账使用。
  • 官方文档和授权条件：Shopify、Amazon、Wayfair、运去哪。
  • 本次核验范围和已知限制：当前覆盖不足的接口不能当成完整订单。
  • 源码参考阅读说明：所有代码为 .reference.txt，只读参考，不应直接执行。
